# 麒麟 ARM64 Docker 应用更新包

本包是应用代码补丁，不是 Docker 镜像，不能使用 docker load 导入。
包含打包时完整应用代码、页面和静态资源，以及 migrate.py，覆盖今天的功能变更。
采用完整应用快照，避免仅复制差异导致遗漏依赖模块。

主要变更：实名评论与回复提醒、发布反馈、公示投票及记名设置和改票、
申请注册及审核、视频播放设置、统一字号、UI1.0/2.0 切换及柔和动效。

不包含数据库、上传附件、头像、日志、测试、Python 环境或离线依赖包。
不包含 app/config.py、run.py、wsgi.py、Dockerfile、Compose 文件和启动脚本，
保留服务器原有配置与启动方式。此次更新不负责更换运行环境。

## 更新前确认

取得原 Dockerfile/Compose 或 docker run 配置，确认容器内项目实际路径、
现有镜像标签、Python 版本、入口命令和所有数据挂载。
重点检查 data/、app/static/uploads/、app/static/avatars/ 及自定义文档存储目录。
如果数据只在容器可写层中，先完整导出并安排持久化，不能直接删除或重建该容器。
如果整个项目目录被宿主机挂载，挂载会遮蔽新镜像中的代码，需要更新实际挂载目录。

本应用沿用 Python 3.8 / Flask 2.0 / SQLAlchemy 1.4 技术栈。
应先在目标服务器相同运行环境、独立测试数据副本上试运行。
本包未在目标 ARM64 Docker 环境执行验证，不假定未知的容器路径。

## 文件校验与更新流程

1. 将 ZIP 解压到独立目录，在解压目录执行 `sha256sum -c SHA256SUMS.txt`。
2. 保留旧镜像和原部署配置。停写后备份数据库及附件；SQLite 存在 WAL 时须使用
   SQLite 一致性备份，或确认服务完全停止后备份完整数据目录（包含 WAL/SHM）。
3. 复制原镜像构建工程，在新构建目录将本包 office_system/ 中的文件合并到
   对应项目目录。不要清空目标目录，不要覆盖服务器原有 app/config.py。
   保留原基础镜像、环境变量、入口命令及挂载配置，使用新标签构建 ARM64 镜像。
   离线环境沿用已有基础镜像和依赖，不运行在线安装或拉取。
4. 使用新镜像、原配置和原持久化挂载，在原容器停止写入后运行一次迁移：
   用容器内原有 Python 解释器在项目根目录执行 `python migrate.py`。
   这里的 python 需换成实际解释器；若迁移失败，停止升级，不启动新服务。
   迁移会为新功能增加表/字段，这是目标数据库的兼容升级，不导入本机数据。
5. 按原部署方式启动新容器。检查首页、登录、原有记录和附件、评论、投票、
   注册审核及 UI 版本切换。浏览器 Ctrl+F5 刷新静态资源。

不要把测试实例连接到生产数据库，也不要让两个实例同时执行迁移。
由于尚未取得部署配置，本包不提供自动覆盖、自动重启或猜测路径的脚本。

## 回滚

停止新容器，恢复旧镜像及原部署配置。数据库迁移后如需完整回滚，应恢复
升级前的一致性数据库备份及对应文件备份；单独换回旧镜像不保证模式兼容。
恢复前另存升级后新增数据，以免丢失期间产生的评论、投票等内容。
